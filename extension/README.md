# MemoIsle Chrome / Edge 网页收藏扩展

从 MemoIsle Web 安装：

1. 点击 MemoIsle Web 顶部的“下载扩展”，保存 ZIP 文件并解压。
2. 打开 `chrome://extensions`，启用“开发者模式”。
3. 选择“加载已解压的扩展程序”，加载解压后的 `memoisle-extension` 文件夹。
4. 首次加载或升级时确认书签、历史记录、通知和网站访问权限；为了能从任意站点读取你右键收藏的那张图片，请在扩展详情页把「网站访问权限」设为「在所有网站上」（若保持默认的「点击时」，右键收藏图片可能无法读取跨站图片）。
5. 重新加载 MemoIsle Web 页面并登录；页面会把当前登录凭证同步给扩展，扩展才能按账号保存书签。
6. 打开 MemoIsle 的“导入浏览器书签”，扩展读取的书签会直接进入预览，无需导出 HTML。
7. 在普通 HTTP(S) 网页点击扩展图标、使用右键菜单或快捷键 `Ctrl+Shift+M`，当前网页会直接存入资料库并弹出收藏结果通知；如果用户已选中文本，选中文本会作为网页正文保存。点击通知里的「撤销」可撤回，点「查看资料」跳转 MemoIsle。扩展也会同步当前浏览器中已打开的网页，供 Web 输入 `@` 选择。
8. 在网页任意图片上点右键，选择「收藏图片到 MemoIsle」，这张图片会直接上传到资料库并弹出「已收藏图片到 MemoIsle」通知，同样支持「撤销 / 查看资料」。
9. 登录后扩展会把最近 30 天的浏览记录同步到服务端，之后只要地址变化就增量上报；在 MemoIsle 点顶栏或侧栏的「浏览历史」，可以按时间范围和关键词翻找，并一键收进资料库。已在资料库里的网址会标成「已收藏」。历史在服务端长期保留，但界面默认只显示最近 30 天。

重复收藏同一网页会提示「网页已在资料库中」，仅提供「查看资料」，避免误撤销原资料。标签页同步在后台独立执行，不会让右键收藏等待全部网页同步完成；返回 MemoIsle Web 时会自动刷新列表和数量。

### 扩展连的是哪个地址

网站下载版（0.5.1 起）会按服务端 `MEMOISLE_WEB_BASE_URL` 自动配置正式网站、API、内容脚本注入范围和更新脚本，保留 9443 等非默认端口。源码目录继续用于本地开发。

升级时请将新版解压覆盖原扩展目录，在扩展管理页点击「重新加载」，再刷新已登录的 MemoIsle 网页。页面会重新同步登录状态。

扩展也会从真正打开过的 MemoIsle 页面学习地址：

- 内容脚本注入 MemoIsle 页面后会登记本页的源；页面再回答自己的 API 地址（开发环境下是 `http://localhost:<Web端口>/api/v1`，由 Vite 把 `/api` 代理到后端）。未登录时也会登记，因此右键收藏总能跳到正在运行的 Web 地址。
- 登录凭证和本页 API 地址通过同一条消息同步，避免页面加载与登录并发时丢失刚登记的 API 地址。
- 生效优先级：`chrome.storage.sync` 里显式配置的 `webBaseUrl`/`apiBaseUrl` > 页面登记 > 内置默认（网站下载版使用部署地址；源码开发版使用 `http://localhost:5173/` 与 `http://127.0.0.1:8000/api/v1`）。
- 只有扩展信任的 MemoIsle 来源才能登记地址，而且只能登记自己所在的源；本地开发端口只接受与页面同源的 API 地址，跨源 API 必须由用户显式配置（例如 `install.cmd <API地址>`）。登记结果保存在 `chrome.storage.local` 的 `memoisle_web_context`。
- 连接失败时打开的 Web 地址会带上 `memoisle_capture_api`，页面提示里会显示扩展实际尝试的 API 地址，便于确认后端端口。
- 本地开发端口范围是 5173–5178（`localhost` 与 `127.0.0.1`），同时写在 `background.js` 的 `LOCAL_WEB_PORTS` 和清单的 `content_scripts.matches` 里，两处必须一致。超出这个范围时，在 `chrome://extensions` 打开本扩展的「服务工作线程」控制台执行 `chrome.storage.sync.set({ webBaseUrl: "http://localhost:5199/", apiBaseUrl: "http://localhost:5199/api/v1" })` 显式指定，显式配置优先于页面登记。

### 浏览历史

- 首次同步（安装、升级或登录后换账号）会**备份浏览器的全部历史**：先二分定位最早一条记录，再从近到远按 7 天窗口扫描，单轮最多推进约 7 个月，断点存 `memoisle_history_sync_state.backfillCursor`。没补完之前，平时浏览（切换网址、启动浏览器）时每次推进一小段；电脑闲置 5 分钟或锁屏时连续推进，直到补完或用户回来，单次最多跑 4 分钟。闲置期间由 `chrome.alarms` 每 5 分钟唤醒一次续跑，全部补完后撤掉闹钟。此后只读取上次同步之后的新访问。
- 回填不是「查一次取 1000 条」：`chrome.history.search` 单次最多返回 1000 条，所以按 7 天一个窗口从近到远扫过去，某窗口命中上限就对半二分继续拆（最小到 1 小时），确保记录不会被单次上限截断。单轮最多收 2 万条，超预算时优先保留最近访问的记录，更早的留到下一轮。
- 触发时机：浏览器启动、登录成功、标签页地址变化（标题变化不算）、以及浏览器清空历史后。
- 未登录时不读取任何历史；退出登录会清空游标，下次登录重新回填基线。
- 上报只包含规范化后的公网 HTTP(S) 网址、标题、最近访问时间和浏览器统计的累计访问次数；`chrome://`、`file://`、本地和内网地址在扩展与服务端双重过滤。服务端按规范化网址合并，访问次数取较大值，重复上报不会虚增。
- 在浏览器里「清除全部历史」时，扩展会以 `replace_all` 请求清空**本设备**在服务端的记录（其他电脑不受影响），但会保留已完成的回填断点，不会重扫旧历史；只删除个别网址则等下一次增量同步覆盖。
- 历史记录只读，扩展不会修改或删除浏览器自己的历史。
- **待发送的改动会落盘**：还没发出去的浏览记录和书签改动保存在 `chrome.storage.local` 的 `memoisle_pending_queues`，包括正在发送、还没收到服务端确认的那一批。MV3 后台空闲约 30 秒会被回收，以前这些改动只在内存里，回收后就丢了；现在后台下次被唤醒时会接着发。服务端按网址和书签 ID 去重，重发不会产生重复。退出登录时一并清空。
- **多台电脑同账号**：每次上报都带设备标识和设备名（按平台显示 Mac / Windows / Linux 等）。服务端按「账号 + 设备 + 网址」分别保存，所以两台电脑访问同一网址互不覆盖；在 MemoIsle 里默认合并展示（访问次数相加），也可以按设备筛选。某台电脑清空浏览器历史只会清掉它自己的记录，不影响其他电脑。
- **设备识别用机器指纹，不是 MAC 地址**：扩展拿不到 MAC（浏览器没有对应 API，且各系统默认对每个 Wi-Fi 随机化 MAC）。改用「系统 + 架构 + 时区 + 语言 + CPU 核心数」算 SHA-256 作为 `hardware_key`，这些属性重装扩展后不变，所以重装后能被认回同一台机器。代价是两台配置完全相同的电脑会算出同一个指纹，因此指纹只作为「疑似同一台机器」的线索。
- **重装与同款电脑靠用户确认**：每次安装另外生成一个随机 `install_id`。指纹相同但 `install_id` 不同时，服务端会在响应里给出 `possible_same_device_id`，Web 端显示「像是同一台机器？合并」按钮 —— 点它就把两台历史合并（重复网址累加访问次数），点「删除」则当作独立设备处理。
- **Cookie 兜底重装**：服务端会把设备 ID 写进 `memoisle_device` Cookie（HttpOnly、一年有效）。卸载扩展会清空 `chrome.storage.local`，但不会删 Cookie，所以重装后即使随机 ID 丢了，也能靠它认回原来那台设备。服务端只在「扩展报了一个未知 ID、且 Cookie 里那台设备的 `install_id` 与本次一致」时才走这条恢复路径，避免同一浏览器里的另一个扩展实例被误吞。
- **为什么不用网页那套指纹**：MV3 的 service worker 没有 DOM，`localStorage`、`document`、`screen`、`matchMedia` 全是 `undefined`，所以屏幕尺寸、字体列表、`prefers-color-scheme` 这些网页端信号在这里拿不到。扩展只能读 `getPlatformInfo()`、`Intl` 区域设置、`navigator.languages`、CPU 核心数与设备内存。也拿不到 MAC 地址和 TLS 指纹。
- 历史记录长期保留，MemoIsle 的「浏览历史」面板默认只展示和搜索最近 30 天；在 **设置 → 浏览历史 → 允许搜索更久的历史记录** 打开开关后，可以按最近 90 天、一年或全部时间检索（默认关闭，避免每次打开面板都扫全表）。面板里可以按标题或网址搜索，也可以选「从 / 到」日期精确查某一天；结果按访问日期分块，日期标题会在滚动时吸顶。点「收藏」把某条记录收进资料库，点「已收藏」直接打开对应条目；每页最多 1000 条，底部「加载下一页」可以一直翻到最早一条；底部「清空历史」只删服务端保存的历史记录，已经收藏进资料库的网页不受影响。

### 右键收藏图片

- 在网页任意图片上点右键，选择「收藏图片到 MemoIsle」，扩展会读取这张图片的字节并上传到资料库，标题取自图片文件名。
- 超过服务端限制（20 MB、单边 12000 px、总像素 5000 万）的图片会先在浏览器本地自动压缩，必要时转为 WebP（GIF 动图只保留第一帧），通知里会说明「已自动压缩后上传：…」的压缩结果；如果当前浏览器无法压缩，会提示改用 MemoIsle 网页端收藏。
- `blob:` 形式的页面临时图片无法直接读取，会提示先另存或使用 MemoIsle 网页端收藏；SVG、AVIF、BMP 等不受支持的格式会被拒绝，不会创建资料。
- 连接不上配置的 API 地址时，通知里会带上扩展实际尝试的地址。

Windows 一键更新：解压目录里的 `install.cmd` 会从后端下载最新扩展包并同步覆盖到当前目录，然后打开 `chrome://extensions`，你在扩展卡片上点一次“重新加载”即可生效。后端地址不是本机时运行 `install.cmd <API地址>`，例如 `install.cmd https://api.example.com/api/v1`。

本地开发也可以在第三步直接选择仓库中的 `extension` 目录。后端位于 WSL 时需让 Uvicorn 监听 `0.0.0.0`，保证 Windows 浏览器能访问后端端口；Web 与后端端口由启动器改到 5174/8011 之类的地址也没关系，扩展会按页面登记的地址回连（见下一节）。

扩展申请 `tabs` 权限，用于读取当前浏览器各窗口中已打开标签页的 URL、标题和图标，供 Web 输入 `@` 选择；申请 `bookmarks` 权限，用于同步书签标题、网址和文件夹路径，供 Web 直接预览并确认导入；申请 `history` 权限，用于读取访问过的公网 HTTP(S) 网页标题、网址、访问时间与次数，同步到 MemoIsle「浏览历史」供搜索和一键收藏；申请 `notifications` 权限，用于一键收藏成功后的系统通知和「撤销 / 查看资料」入口；申请 `alarms` 与 `idle` 权限，用于在电脑闲置或锁屏时继续补全浏览历史：`idle` 只读取「使用中 / 闲置 / 锁屏」三种状态，不记录任何操作内容，`alarms` 在历史补完后即撤销；申请 `activeTab` 与 `scripting` 权限，仅在用户明确触发扩展动作时读取当前页的选中文本。为了支持「收藏任意网页上的图片」，清单还声明了 `<all_urls>` 主机权限：扩展只在用户右键点击某张图片并选择「收藏图片到 MemoIsle」时，用它读取这张图片的字节，以及访问当前登记的 MemoIsle API 主机；扩展不会用它读取页面内容、Cookie 或表单。源码开发版的内容脚本只匹配本地 Vite 开发地址（`localhost`/`127.0.0.1` 的 5173–5178 端口，与 `LOCAL_WEB_PORTS` 一致），后台还会校验标签页来源与配置的 Web 地址一致后才写入登录凭证或登记地址，且页面只能登记自己所在的源；凭证保存在扩展本地存储，不会写入 URL。扩展不会读取 Cookie、表单或未选中的页面正文；选中文本最多保存 10000 字；浏览历史只读，仅在已登录 MemoIsle 时同步，退出登录即停止并清空游标。打开网页快照只保留 HTTP(S) 公网页面，浏览器内部页、本地文件和内网地址会被过滤；书签中的非 HTTP(S) 地址会在导入预览中标为无效，不会创建资料。图片收藏目前只接受 HTTP(S) 与 `data:` 图片地址；本地 `file://` 图片暂不支持右键收藏，建议直接用 MemoIsle 网页端从文件选择器收藏。网站下载版会自动将内容脚本 Web 地址和默认回退地址配置为正式同源地址；如需进一步收窄权限，可把 `<all_urls>` 换成图片所在站点的具体匹配模式。

Chrome 不允许普通 Web 页面无授权读取浏览器书签，因此该能力必须由扩展提供。没有安装新版扩展时，Web 仍保留 Chrome 书签 HTML 本地解析入口作为备用方式，原始 HTML 文件不会上传。

无需启动浏览器即可执行扩展触发逻辑的自动化回归测试：

```bash
cd extension
npm test
```
